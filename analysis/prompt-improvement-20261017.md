# Prob001 / Prob003 提示改进的依据与边界

分析批次：`hard-case-five-round-01/real-all-20261017-073813`，模型为 V3-0324。第二题已替换为 Prob023；以下原建议现已按用户要求接入，实装范围见文末。尚未调用真实模型验证效果。

## Prob001：出题能力覆盖不足

五轮已准入的练习主要变更匹配常量，另有一题变更比较位宽。所有在线组、无经验参考组均修复练习，但每轮经验候选在固定验证上都是0/4，低于基线2/4，所以没有经验被接受。存档修复显示验证中模型只改回匹配常量，没有同时修复移位方向或保持行为。

两组题还存在实质重复：第1/2轮只在二进制常量下划线写法上不同，第4/5轮亦如此。对实际 `admission/candidate.v` 规范化二进制常量中的下划线后，两个文件对分别完全一致。当前 token 文本去重没有识别这种数值等价写法。提示可以减少重复倾向，但可靠拒绝这类重复需要程序规范化数值，不能只靠一句“不要重复”。本次未改动这部分核心逻辑。

建议给 Red 的机制提示：

> 五轮围绕输入历史位序、历史位截取、比较条件、寄存输出时机及输出保持展开。若两组已成功修复某类单点错误，后续换机制，不要继续换匹配常量或下划线。先单点练习，后组合两个已覆盖机制；根据真实公开修复轨迹选择下一题。不得复制固定考试或验证变体。

这能改变练习覆盖方向，但不保证模型遵循、不保证经验迁移，也不证明此前候选退步完全由经验导致。样本少，且远端采样不保证相同随机性。

## Prob003：有效出题已有，主要瓶颈在修复理解

两轮准入题均是单个中间状态转移的真假分支交换，两组均未修复。实际修复回答却去改两个终止状态为 idle，错误解释为“非重叠必须回 idle”。这丢失连续输入的组边界首位，说明需要先理清时钟采样与每组六位之间的关系。仅要求 Red “再难一些”不针对这个问题。

建议给 Red 的机制提示：

> 先选择易于逐拍定位的单个中间转移错误，保持复位和输出译码不变。若两组都失败，下一题降低组合程度并换可达路径，不继续堆叠缺陷；已有成功修复后，再练习相邻输入组边界。用公开规范及前轮真实结果选择机制，保持每个时钟沿的输入消费与输出相位约定，不复制考试变体。

建议给 Blue 的通用修复提示：

> 对照规范和公开输入轨迹逐拍列出状态、已消费位数、当前输出及下一输入所属分组；检查连续组之间是否遗漏或重复消费某一位。保留原输出相位，不要仅凭“非重叠”一词重写所有组边界。

这属于规范解释和调试方法，不是提供最终考试补丁。若修改 Blue 提示，应对无经验组与经验组同时采用，并在新批次重建基线；不能与旧提示的成绩直接归因为学习收益。

## 能支持的结论

有针对性的提示有改进空间。Prob001 应提高练习机制多样性与组合诊断覆盖；Prob003 应结合逐拍修复约束与由易到难的出题。程序去重、Blue 自身修复能力和晋升样本覆盖也会影响结果，提示不是保证。效果需新批次实测，不能用本地假回答 smoke 当成效果证明。
