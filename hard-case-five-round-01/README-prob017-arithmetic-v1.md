## 准确的实验机制

1. 本批第一批模型请求只用于无经验组 B₀：先考完3道独立考试题，每题重复2次，共6次作答。尚不建立验证基线、不启动 Red、不训练。
2. 若6/6全部正确，说明这套考试在本次无经验测量中没有体现区分度，整批正常停止，保存前测证据。单题2/2不停止其他题。若存在上下文超限等无效测量，则单独停止，不能将其当成答错并据此判断难度。
3. 若测量完整且不是6/6，写入 `initial_exam_gate.json`，封存每题 `initial_exam.json` 及请求、回复和评测证据。这个成绩直接作为最终静态组成绩，后续不再调用静态组重考。
4. 三题各自建立独立验证基线并执行五轮对抗流程。经验不跨题共享；只有对抗组在线公开练习结果能产生候选经验，独立验证决定晋升。前测结果、答案、评测反馈不进入训练提示或经验。
5. 全部五轮流程完成后，写入 `training_barrier.json`，绑定各题 B₅。此后只让对抗组做同一套考试，每题重复2次；与封存的 B₀ 前测比较。考试不学习、不调参，不测 B₁至B₄。

仍为**3道题、每组6次作答**。固定验证仍为每题2道、各重复2次，验证4/4不是考试满分。前测与最终比较使用相同计分规则：公开修复通过且独立评测通过才计正确。训练及对抗组考试前校验前测证据，防止成绩或原始记录被改动。

即使初始验证满分，或连续两轮未形成经验，也继续执行五轮流程和最终考试。五轮不等于保证有五道有效练习：未获得合格在线候选时如实记录空轮，不进行 Blue 练习、不计为成功，也不补人工题。没有提升本身就是实验结果，不以此取消对抗组考试。每轮Red一次请求、无格式纠错、每个Blue样本至多两次功能尝试时，完整流程常规预算243次请求；包含Red纠错及格式纠错的硬上限486次，每题162次。通过即结束、无候选空轮及无候选经验时，会少于上限。旧版129/258次预算不再适用，旧运行保留原有预算与协议。

## 公开编译与仿真反馈

两组每次作答最多进行两次功能尝试：首次提交后真实编译、运行公开测试；若编译或功能失败，返回失败候选、公开诊断、失败周期及实际/期望值（测试有提供时），允许再改一次。第二次仍失败就结束，通过则立即结束，不无限重试。

每次功能尝试另允许一次 JSON 格式纠正，所以每个作答样本最多4次请求。连续格式不合法不触发功能重试；网络或工具基础设施错误不伪装成需要修改的功能错误。在线组、静态组、独立验证、B₀前测与B₅考试采用同一预算。格式纠正步骤不新增编译或仿真反馈。

考试的本次公开反馈只在当前作答内部使用，不写入训练经验，也不传给下一个考试样本。隐藏评测结果不进入修复提示。只有最终公开测试通过的在线练习能生成候选经验；失败仍只反馈给 Red，不冒充成功经验。

## 后两题的难度控制和经验

Prob023 的提示要求逐拍核对 Gray 解码、加法寄存器和输出，避免重复叠加隔拍使能或盲目改变有依赖的赋值方式。Prob017 要求核对更新前计数值、4位/7位计数器回绕、分频模式、输出阈值、参数变化及异步低有效复位。

两题前两轮只允许单一局部缺陷。后续必须已有至少两次不同在线练习的公开修复成功，且上一轮修复成功，才允许扩展到边界；仅第五轮在该门槛下允许跨两个表达式的关联变更；全局最多两处兼容token替换。上一轮失败、格式无效或空轮都保持单一局部缺陷，不按轮次强行加难。资格检查前由程序拒绝越级候选，并把原因反馈给 Red。

基础阶段中，Prob023 只改转换表达式右侧，保护寄存器节拍；Prob017 只改非复位时的计数、模式或输出寄存器右侧表达式，保护复位、参数声明、接口和时钟。既有真实编译、功能、结构、去重和考试/验证隔离检查仍全部执行，没有人工替代题。

Prob017 的基础阶段只允许一个局部表达式缺陷。Red 收到从公开原件提取的可修改位置、未修改的表达式及历史尝试计数；这些不是预制缺陷或备用题，修改仍全部由 Red 在线生成。

所有已物化候选（包括被拒者）按规范化实现去重，改空白或换编辑上下文也不能重试同一实现。公开资格失败只限制本轮失败的具体表达式位置，不封死全部表达式机制；同批后续候选和一次纠正请求仍可选择其他合法位置。Red 每轮仍最多两次请求、每次最多4个候选，预算不增加。

成功经验除原补丁和公开测试结果外，还保存可追溯的修改行摘要及迁移时需要复查的公开设计条件。摘要只来自真实公开成功样本，不额外调用模型；独立验证仍要求严格增益且不损失已有认证成绩，才保留经验。这不保证模型在五轮内成功或最终考试提升。

## 在线生成与题目资格保证

正式训练**不使用人工预制备用题、固定练习池或离线通过的替代题**。这些旧文件只在历史版本和离线测试中保留，不在当前生产源码清单和冻结计划中。

每轮 Red 最多发出两次在线请求（首次加一次带反馈纠正），每次可返回最多4个不同机制的候选。候选都必须来自该次模型原始回复，原始回复先落盘，再逐个筛选；只选第一份通过资格检查的候选进行本轮两组修复，不使用 Blue 表现、隐藏评测或考试成绩挑题。最多8个候选是两次请求的上限，不增加本轮练习题数。

程序把修改限制在两处以内的兼容语法节点替换：同位宽已知值常量、整数索引、同组运算符、已声明状态常量；也允许交换一个已有双项拼接的两项。不允许追加 if 条件、插入新分支或自由重写语法。仍检查接口/声明/注释边界、编辑预算和数值等价去重。

每个候选必须满足真实本地编译、**W_bug失败且W_preserve通过**、结构检查、与考试/验证/开发种子分离及不重复，才有资格交给 Blue。通过语法约束不能替代功能检查；有限公开检查通过也不等于数学上证明任意输入都符合全部规范。

首次失败会收到具体原因和失败编辑，下一次请求优先纠正并避开已失败机制。两次请求仍没有合格题时，本轮写入 `empty_practice.jsonl`，保留原经验并继续下一轮及统一考试。`qualified_practice_slots`、`empty_practice_slots`、`human_prepared_replacements=0` 分别报告有效练习、空轮和未使用人工替代题；不得把空轮宣称为有效训练。

**能够保证的是进入 Blue 的题满足冻结的资格检查，不是保证有限额度内模型每轮一定产出合格题。** 凭据、预算、材料完整性及工具基础设施错误仍明确停止。不能用人工题或无限重试来伪造生成成功。
