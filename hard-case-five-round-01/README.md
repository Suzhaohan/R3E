# 三题五轮：加强训练反馈，专项启发只用于红队出题

当前三题：交接包 Prob003 的 eval_miss_branch 变体、Prob023 Gray 计数器、Prob017 arithmetic 分频器。
模型为 2024-12-26 首版 DeepSeek V3（OpenRouter `deepseek/deepseek-chat`）。每次新建批次，从空经验开始。

用户要求的针对性提示，是让红队生成有助于积累有效修复经验的练习，
不是直接指导静态组或对抗组解题。本版修正此前扩展到蓝队的提示。

- 红队保留各设计的出题方向、按本轮公开结果调整难度、真实资格筛选和去重。
- 所有蓝队角色使用相同的通用指令、题面、缺陷 RTL、公开测试及当前作答的真实反馈。
  静态组、在线组、验证、前测、最终考试均不注入人工专项解题提示或人工分析工作表。
- 对抗组经验只来自本次训练中自身成功修复的补丁、题面摘录和公开测试结果。
  经验按 token 差异提取原始缺陷代码与成功提交的上下文，附公开测试失败/通过证据；
  checks_on_transfer 为空，不附加人工编写的专项解题建议。
  成功经验先供后续训练连续使用；考试经验必须在固定验证上严格提高、且逐个样本不退步。
  验证持平仅保留为训练经验，不能进入考试。失败修复不产生经验。
- 历史答案和经验不进入新批次。题面和验收规则不变；Prob017 保留对原文数值矛盾的公开说明。

## 本次训练反馈修改

- 在线对抗组与无经验参考分支，每道练习均最多四次功能尝试；公开测试通过即停止。

## 保持原有实验机制

1. 无经验组先做三题考试，各重复两次；有效测量全部正确则整批停止。
2. 否则封存前测，作为最终静态成绩，不让前测答案或反馈进入训练。
3. 三题各自运行五轮，经验不跨题共享；全部训练结束后冻结，再统一进行对抗组考试。
4. 验证每题两道、各重复两次；考试每题重复两次，考试之间不学习。
5. 练习中两分支均最多四次功能尝试；两组考试与验证均最多两次，每次最多一次格式纠正。
   公开编译和仿真反馈用于当前作答内修正；隐藏评测不进入提示。
6. 红队每轮最多两次请求、每次至多四候选；保留原真实资格检查。
   不使用人工备用题，未生成合格题时如实记录空轮。

常规请求上限303次，含格式纠正等硬上限606次（每题202次）；输出16000、上下文128000 token。
这是次数与 token 限制，不是金额硬上限。固定验证通过不保证考试满分或稳定提升。
本次完成离线检查及独立小样本实测，没有启动新的完整批次。小样本不是正式考试成绩；详见 local-patch-validation.json。

## Prob003 五轮红队出题引导

1. 优先最后一位的匹配判断，保留前面五位、输出和组边界。
2. 优先非匹配路径的末段推进，练习不匹配后仍消耗完整组六位。
3. 向非匹配路径较早位置推进，区分“当前第几位”和“前缀是否仍匹配”。
4. 当前运行已成功修复非匹配路径推进后，进入单个组边界转移错误；否则继续非匹配路径末段练习。
5. 已解锁边界时，用不同局部缺陷和输入历史检查边界迁移；不得退回无关的中间状态题。未解锁则继续当前非匹配路径阶段。

阶段对应的代码位置现在是硬约束，具体缺陷仍必须在线生成，不能按预制清单替换。第一轮限 s5，后续先限非匹配路径，再按本次公开成功记录解锁 s6/sf6。
前三轮边界修改被硬性拒绝；后两轮只有本次非匹配路径公开成功记录才能解锁边界，始终最多一处 next-state RHS。
输出、复位、idle/default 和多处转移修改均禁止；仍须通过编译、功能见证、结构及考试/验证碰撞检查。
失败重试保留当前教学方向，根据公开的真实失败补丁换一个合法位置，不向蓝队附加专项工作表、修法或考试答案。
这些引导只给红队。蓝队各角色继续使用同一个通用接口，经验只来自当前运行成功案例。
五轮、三题、训练4次/考试验证2次及303/606请求预算不变。
本次修改只做离线验证，未自动启动付费运行；实际模型学习收益需新批次测量。

## 小规模迁移诊断

transfer_probe.py 使用新在线生成的两道不同练习，先完成一题学习，再让无经验和有经验分支做同一新题。
不使用正式考试题或验证题，不导入历史经验。两分支都是四次功能尝试、无格式重试，种子相同。
最多14次真实请求（两次红队请求、三次修复各最多四次）；第一题没有成功经验则提前停止，不重复筛选到正结果为止。
这是单次探索性对照，与正式五轮考试协议不同；即使对抗分支胜出，也不能称为稳定统计优势。
所有结果都保存，支持明确的失败/持平报告。

## Prob003 出题接口修正

上一轮的实际失败是：模型把无条件转移改成三元条件，违反 token 只能替换的规则，
又重复这些已拒绝的提案，导致四个空轮。位置收紧后仍让模型自由拼 RTL 的接口不够可靠。

当前 Prob003 红队不再返回 find/replace 或完整 RHS，而是从当前公开源代码导出的
structured_transition_actions 中选择 action_id，并自行说明触发历史和规范依据。
动作只允许替换现有、已声明的状态常量，或交换同一个已有三元表达式的两端状态。
程序按模型选择生成精确的局部替换，保持语法 token 数量；不能插入条件、分支或新声明。
动作表只是编辑语法，不是人工备用题，不包含预计算资格结果或 Blue 答案；
实际选择必须来自本次模型输出，仍须通过编译、公开功能见证、结构、考试/验证隔离和去重。
不自动选题、不使用离线覆盖检查生成的候选替代模型提案。

同一轮失败只排除已尝试的具体实现，不再封锁整个状态位置。
本批次此前尝试过的规范化实现，会从下次请求的动作表移除；不同运行不复用这些记录。
旧式自由编辑输出、伪造或重复 action_id 会被拒绝并收到一次有上限的纠正请求。

真实 EDA 离线穷举检查在 structured-red-space-validation.json：末位阶段25个合格不同实现，
非匹配末段24个、较早非匹配路径36个、边界48个（另两个与冻结评测题重合已排除）。
这些计数证明编辑空间够用，不能证明真实模型一定正确选择或学会修复。
启动前必须通过此检查的状态、候选覆盖数量和当前接口/阶段代码哈希校验；缺失或过期则拒绝付费启动。
完整补丁及原始资格结果保存在 structured-red-offline-qualification-v1/，仅供离线复核。
Prob023、Prob017 的红队继续使用原接口，全部蓝队解题接口和两组预算保持不变。
此次修正不调用真实模型，不宣称真实模型正确率已经提升。
