# run06 完整运行指南：从打开终端到查看结果

这份指南只适用于 `deepseek-run-06`。第一次运行按第1～7步执行；中断恢复看第8节；只看已有结果看第9节。第10节是另开一场独立实验，不是普通恢复步骤。

除专门注明“在自己电脑执行”的 SSH 命令外，本文命令都在服务器终端、项目根目录执行。不要把代码框前后的解释一起粘贴进终端。

## 1. 进入正确目录

打开服务器终端。如果你使用 VS Code Remote SSH，就在已经连接服务器的窗口里打开终端。

执行：

```bash
cd /data2/huangyc/R3E-aic-ic-2026-latest
pwd
ls deepseek-run-06/run.sh deepseek-run-06/client.json
```

`pwd` 应显示 `/data2/huangyc/R3E-aic-ic-2026-latest`，`ls` 应找到两个文件。后面的命令统一带 `deepseek-run-06/`，因此保持在这个目录即可。

如果提示目录或文件不存在，先检查是否连接了正确服务器、是否进入了上述项目目录。

## 2. 建议在 tmux 中运行，避免断开 SSH 后任务丢失

如果你已经在一个准备长期保留的 tmux 窗口里，可以跳过这一步。

创建一个窗口：

```bash
tmux new -s r3e-run06
```

进入后，再确认工作目录：

```bash
cd /data2/huangyc/R3E-aic-ic-2026-latest
```

如果提示同名窗口已存在，进入已有窗口，不要同时开第二份实验：

```bash
tmux attach -t r3e-run06
```

启动实验后，需要暂时离开时，先按 `Ctrl+B`，松开，再按 `D`。这样只是离开窗口，实验继续运行。回来时执行上面的 `tmux attach`。

不要把 `Ctrl+C` 当成离开窗口：它会中断当前前台命令。

## 3. 检查 Python 和仿真工具

在上述终端执行：

```bash
.venv/bin/python --version
command -v iverilog
command -v vvp
command -v yosys
```

应看到 Python 3.11 或更高版本，以及三个工具的路径。这台项目环境已有 `.venv`，启动脚本会自动使用它，不需要额外执行 `activate`。

如果 `.venv/bin/python` 不存在，但你有另一个已装好项目依赖的 Python 环境，可以指定其解释器：

```bash
export R3E_RUN_PYTHON='/你的环境的完整路径/bin/python'
```

这是一条备用设置，不要原样执行占位路径。该环境需要项目依赖，包括 `numpy`、`openai`、`PyYAML`。如果仿真工具没有路径，需要先由环境维护者安装好工具，再继续实验。

## 4. 设置模型连接和密钥

必须在**将要执行实验的同一个终端或 tmux 窗口**里设置。新开一个终端，不一定还保留原窗口的环境变量。

先设置本项目配置使用的接口地址：

```bash
export R3E_PILOT_BASE_URL='https://api.deepseek.com'
```

再执行下面三行。第一行执行后会等待你粘贴自己的 API 密钥，然后按回车；输入不显示在屏幕上，这是正常的。

```bash
read -r -s -p '粘贴 API 密钥后按回车：' R3E_PILOT_API_KEY
export R3E_PILOT_API_KEY
printf '\n'
```

这里只需要密钥本身，不要附加 `Bearer `。不需要把密钥写进代码、配置文件或聊天消息。

检查是否设置成功，下面的命令只显示“已设置/未设置”，不会显示密钥：

```bash
if [ -n "${R3E_PILOT_API_KEY:-}" ]; then echo '密钥已设置'; else echo '密钥未设置'; fi
```

客户端配置在 `deepseek-run-06/client.json`。当前文件配置的模型名称是 `deepseek-flash`。已有完整配置，无需为了启动再修改它。一次实验开始后，模型配置、代码和预算需要保持一致，才能断点恢复。

## 5. 正式启动前检查一次

执行：

```bash
bash deepseek-run-06/run.sh check
```

这一步不调用模型、不消耗模型调用额度。看到 `"ready": true` 才表示本地运行条件通过。

检查项含义：

| 输出字段 | 通俗解释 | 正常值 |
|---|---|---|
| `tools` | 编译、仿真工具能找到 | `true` |
| `dataset_separation` | 练习题、检查题、最终评分题的隔离检查通过 | `true` |
| `committed_source` | 源码已固定，没有未记录的修改 | `true` |
| `client_config` | 模型连接配置完整 | `true` |
| `credentials` | 当前窗口读到了密钥和接口地址 | `true` |

`credentials: true` 只说明变量存在，不证明密钥有效、账户有余额或接口一定能连通。

如果需要单独排查网络，可以执行：

```bash
bash deepseek-run-06/run.sh network-check
```

它检查网络和 TLS，不发修题请求、不验证账户余额。`tls_connected: true` 表示已建立连接；接口对未认证的探测返回非200状态，并不必然代表网络不通。

只有在需要确认密钥和模型能否真正调用时，才额外执行：

```bash
bash deepseek-run-06/run.sh probe
```

`probe` 会发出 **1次小型真实模型请求**，可能产生费用。成功时显示 `"ok": true`。它不启动五轮实验，也不算修题成绩。这是可选排查步骤，不要求每次都执行。

## 6. 一条命令启动完整实验

执行：

```bash
bash deepseek-run-06/run.sh start
```

正常启动无需另外执行 `init`、`a0`、`b`、`a` 或手动添加题目。程序会依次完成：

| 阶段 | 程序在做什么 |
|---|---|
| 准备 | 固定本次实验配置，启动或连接网页 |
| A 初始评测 | 用原始固定策略测一次 A 的起点 |
| B 初始评测 | 测 B 的起点，此时 B 也没有经验 |
| B 五轮探索 | 出题、尝试修复、记录经验、检查并决定策略能否升级 |
| B 最终评测 | 使用最终选定的策略和已确认的记忆做评分题 |
| A 最终评测 | 用原始固定策略、空记忆做同一套评分题 |
| 生成比较 | 核验两组记录，生成 `comparison.json` |

B 的五轮编号是 `R000`、`R001`、`R002`、`R003`、`R004`。每轮最多搜索5个候选策略；每次修一道题仍是3个候选修复。两个“候选”不是同一个数量。

默认预算：

| 实验组 | 整场模型调用上限 | 整场保守 token 预留上限 |
|---|---:|---:|
| A | 400次 | 12,000,000 |
| B | 6,000次 | 120,000,000 |

这些数字是停止上限，不是计划必须花满的量，也不是费用报价。失败调用和恢复重试也计入预算；预留 token 不是服务商账单上的实际 token 数。

运行时间取决于模型响应、仿真耗时、实际候选数和重试情况，不能用调用上限推算成固定时长。启动后，终端会不断输出阶段和结果。需要离开服务器连接时，用第2节的 tmux 分离方式。

## 7. 打开网页，查看进度和最终结果

### 7.1 浏览器就在服务器上

打开：

```text
http://127.0.0.1:8086/
```

选择左侧 **Adversarial Arena**。本次 A/B 实验在这里看。Repair Studio 的教学案例、其他历史结果页不是本次实验的成绩。

### 7.2 浏览器在自己的电脑上：使用 VS Code

在 VS Code 的“端口 / Ports”面板转发服务器端口 **8086**，点击转发后提供的本地地址。若 VS Code 为它分配了别的本地端口，就用面板实际显示的地址。

### 7.3 浏览器在自己的电脑上：使用 SSH

下面这条命令在**自己电脑的终端**执行，不是在服务器终端执行。替换“用户名@服务器地址”：

```bash
ssh -N -o ExitOnForwardFailure=yes -L 18086:127.0.0.1:8086 用户名@服务器地址
```

保持这个终端运行，再在自己的浏览器打开：

```text
http://127.0.0.1:18086/
```

这里本地是18086，服务器是8086。若 SSH 使用非默认端口，在 SSH 命令中加入 `-p 实际端口`。

地址使用 `http://`，不是 `https://`。不要直接双击源码中的 HTML 文件。

### 7.4 页面按钮与更新方式

- 刚启动时，A 初始评测或 B 初始化可能尚未完成，网页暂时没有可展示的完整回合，这是正常的。
- 运行中刷新网页，获取最新完成并通过核验的轮次。当前保留的原版页面不是每3秒自动拉取新进度。
- “播放已记录轮次”“下一轮”是**回放已经完成的记录**，不会发起模型调用、不会启动或推进实验。
- 最终报告生成后，刷新页面，再播放到最后一轮，或点击“下一轮”直到末尾，即可查看最终评分区域。
- 页面沿用了原版部分静态介绍，若看到“57个案例”“M0固定”等历史介绍文字，不应把它当作本轮配置：run06 实际使用20道原始题，A空记忆，B使用本次经验。具体范围见第11节。

终端也能查询当前状态，不会触发模型调用：

```bash
bash deepseek-run-06/run.sh status
```

常见字段：`initialized` 表示是否已经初始化；`completed_rounds` 是已完整完成的轮次；`frozen` 表示该组最终记录是否已固定；`budget.calls` 是已经占用的模型调用次数。

需要看正在执行什么时，在另一个服务器终端进入项目目录后执行：

```bash
tail -n 50 -f deepseek-run-06/logs/arm-start.log
```

结束这个 `tail` 查看窗口时按 `Ctrl+C`，只会停止日志查看，不会停止另一个 tmux 窗口中的实验。如果日志还不存在，说明尚未通过 `start` 启动过。

### 7.5 怎样判断真的完成了

整场正常完成后应有：

- B 的 `R000` 到 `R004` 五轮记录；
- `deepseek-run-06/arm-a/frozen_arm.json`；
- `deepseek-run-06/arm-b/frozen_arm.json`；
- `deepseek-run-06/comparison.json`。

也可以执行：

```bash
bash deepseek-run-06/run.sh compare
```

它只读取、核验和整理已完成结果，不调用模型。输出 `"valid": true` 才表示比较报告核验通过。任意一组尚未完成时，不能用它提前生成最终成绩。

最终评分共6道题，每题做3次，即每组18次尝试，分为 `red-heldout` 的6次和 `strider-subset4` 的12次。`static_repaired` 是 A 成功次数，`adversarial_repaired` 是 B 成功次数；`gained_pairs` 是 B 比 A 多修好的对应尝试，`lost_pairs` 是 A 能修好但 B 没修好的对应尝试。

“流程完成”“有策略晋升”“最终 B 比 A 好”是三件不同的事。程序完成不等于一定有晋升，晋升也不等于最终测试一定提高。

## 8. 中断后怎样继续

先区分：只是断开了连接，还是实验进程真的停止了。

1. 如果用了 tmux，先执行 `tmux attach -t r3e-run06`。如果原命令还在输出，就让它继续，不要启动第二份。
2. 如果命令已停止，在该窗口重新确认项目目录，以及第4节的密钥、接口地址。
3. 重新执行和第一次相同的启动命令：

```bash
bash deepseek-run-06/run.sh start
```

同一目录重复执行 `start` 是继续**同一场实验**：已经完成并核验通过的结果会复用，本次积累的经验也保留，不会从第一题重新付费跑一遍。

程序会有限次数重试连接或响应格式问题；回答被截断时可按记录扩大输出空间，最高16384 token。达到重试或长度上限仍不能完成时会停止并保留进度，不会把半截回答当作成功。

恢复时，不要删除 `arm-a`、`arm-b`、`baseline.json` 或缓存；不要改源码、模型配置或已经固定的预算。预算真的耗尽时，原命令不会自动扩容；这不是普通网络重试问题，应先核对已完成记录和预算，再决定后续安排。

如果刚才没有使用 tmux、连接断开后不确定原任务是否还活着，先查看日志和状态。`pipeline.json` 可能停留在进程退出前的状态，不能仅凭其中的 `running` 判断进程仍存活。

## 9. 已经跑完，只想看结果

如果8086的页面已经能打开，直接打开它即可。

如果网页服务已停止，在服务器项目目录执行：

```bash
bash deepseek-run-06/run.sh view --port 8086
```

这只启动观察页面，不调用模型，不需要密钥，也不会重新跑实验。它是前台服务，该终端需保持打开，或放在 tmux 中运行。

如果显示端口已占用，先打开现有8086页面确认是否是本实验。不要为了看结果重跑整场实验，也不要直接结束未知进程。

## 10. 如果要从零再做一场独立实验

**这不是首次运行 run06 时必须执行的步骤。** 当前目录没有初始化过时，直接按第1～7步即可。

同一目录再次 `start` 会恢复旧状态，不能代表一场新的独立实验。要从空记忆开始另一场实验，可以在保留已有结果的情况下，只复制源码和启动配置，建立新目录：

```bash
(
  set -e
  cd /data2/huangyc/R3E-aic-ic-2026-latest
  mkdir deepseek-run-06-fresh-001
  cp -a deepseek-run-06/source deepseek-run-06/recovery deepseek-run-06/run.sh deepseek-run-06/client.json deepseek-run-06-fresh-001/
)
```

若 `mkdir` 提示目录已存在，这段命令会停止。换一个从未用过的新目录名，不要往已经有结果的目录覆盖复制。

新目录不复制 `arm-a`、`arm-b`、`baseline.json`、`comparison.json` 或旧经验。它保留原版代码和工具配置，自己初始化新状态。

密钥仍在同一个终端环境中时，运行：

```bash
bash deepseek-run-06-fresh-001/run.sh start --port 8087
```

新实验页面使用8087，避免误打开旧实验的8086页面。使用 VS Code 时转发8087；使用 SSH 时相应把转发的服务器端口改成8087。此后恢复这一场实验，也使用这条新目录、新端口的命令。

## 11. 本版到底运行哪些内容

### 11.1 题目与防退化

保留原来的五轮、每轮最多五个候选策略和最终评分题。原始题总数20道：4道练习题、6道晋升考试题、4道独立防退化题、6道最终评分题。红队运行中生成的新题另行记录，不计入这20道原始题。

防退化只在原来两道锁存器题上，新增一道独立译码题和一道独立时序计数题；加法器、多路选择继续使用原流程已有的练习检查。没有额外的最终16题流程，也没有历史经验预览流程。

可以把防退化理解成：新方法做完题，再抽查几个原本会做的题，看是否被新方法弄坏。

这是主要类型的代表检查，不是所有错误的完整覆盖。尤其最终评分中的状态机错误，目前没有单独的状态机防退化题，仍可能漏检。通过检查不能保证最终 B 一定不低于 A。

### 11.2 A、B和经验有什么区别

- **A：固定做法，没有错题本。** 全程使用原始策略、空记忆。
- **B：可以改做法，有本次实验的错题本。** 初始是空的，做过题后记录怎么改、编译是否通过、功能是否正确；成功失败都保存。
- 下一轮开始前，尝试更新可用经验。只对提示中实际受到经验变化影响的代表题复查一次；最多涉及四道防退化题和原有练习中的一题加法器、一题多路选择。观察到退步就暂不使用这次更新，但记录仍保存。
- 修新题时，只找本次实验里相关的几条记录提醒模型，最多六条；不是把整本记录都塞给模型。模型仍要重新提出修改，由仿真确认对错。
- 每轮中途不换记忆。最后一轮新记录也会保存，但最终评分使用最后一轮开始时已确认的记忆，不边考试边学习。
- 同一实验断点续跑保留记忆；独立新实验从零开始。整个过程不修改大模型本身的参数。

### 11.3 文件去哪里找

以下路径均在 `deepseek-run-06/` 内；若使用第10节的新实验目录，则替换为新目录：

| 路径 | 内容 |
|---|---|
| `logs/arm-start.log` | 一键启动的终端输出 |
| `logs/web.log` | 由一键启动器新建网页进程时的输出；复用已有网页时不一定有此文件 |
| `pipeline.json` | 最近写入的流程阶段，不是进程存活证明 |
| `arm-a/budgets/total.json`、`arm-b/budgets/total.json` | 两组累计调用和保守预算预留 |
| `arm-b/rounds/R000` ～ `R004` | 五轮红蓝探索和检查记录 |
| `arm-b/replays/` | 本次修复重放的原始记录 |
| `arm-b/experience/archive/library.json` | 已完成轮次归档的经验摘要 |
| `arm-b/experience/R000.json` 等 | 每轮真正使用的记忆 |
| `arm-b/experience/proposals/` | 提议采用的记忆，包括没有通过检查的更新 |
| `arm-b/experience/guards/` | 记忆更新检查结果 |
| `arm-a/frozen_arm.json`、`arm-b/frozen_arm.json` | 两组最终固定的结果 |
| `comparison.json` | 最终 A/B 比较报告 |

A没有经验归档。经验摘要通常在完整轮次结束后整理；某题执行中被中断时，先看原始记录和恢复缓存，不能只凭摘要条数判断记录是否丢失。

## 12. 常见问题怎么处理

| 看到的情况 | 先怎么处理 |
|---|---|
| 找不到 Python 环境 | 检查 `.venv/bin/python`，或按第3节指定已有环境 |
| `credentials: false` / 没有模型 API 密钥 | 在执行实验的同一个终端重做第4节；接口地址也要设置 |
| 401、认证失败 | 核对密钥是否有效，是否多复制了空格或其他文字 |
| 余额或额度错误 | 按接口返回信息检查账户状态；反复重启不能解决余额问题 |
| `committed_source: false` | 用 `git -C deepseek-run-06/source status --short` 查看变化；不要跳过源码检查。实验开始后的修改需要先核对，不能随意重写原基线 |
| `dataset_separation: false` | 题目配置或相关文件检查未通过，保留原始报错，不要删除隔离校验来强行运行 |
| 网络断开 / TLS连接失败 | 先用 `network-check` 检查网络；恢复网络后使用原命令续跑 |
| JSON格式错误 / 回答截断 | 程序会按有限恢复规则处理；持续失败时保留日志，不能直接把错误输出当结果 |
| 预算耗尽 | 先看对应 `budgets/total.json`；恢复时不能随意改变已固定预算 |
| 8086打不开 | 确认网页进程存在、使用http；远程浏览器还要检查端口转发 |
| 8086端口已占用 | 先查看该页面是不是本实验；若是，直接复用；若不是，在启动时指定空闲端口，例如 `--port 18086`，并转发实际端口 |
| 页面没有新轮次 | 刷新网页并查看终端日志；页面只展示已完成并核验的回合 |
| 五轮完成但没有升级 | 查看各轮原因，这是允许的真实结果，不代表程序一定报错 |
| 比较报告没有生成 | 先确认 A、B 都完成；只完成 B 或只打开网页都不算整场完成 |

当前网络恢复默认仅对模型接口采用直连。如果你的服务器必须通过已配置好的环境代理访问接口，可在启动前设置 `export R3E_NETWORK_ROUTE=environment`。同一次实验恢复时保持原来的网络路由设置，不要关闭 TLS 证书验证。

## 13. 分步命令，仅供需要手动控制时使用

平时使用第6节的 `start` 即可。下面这些是同一流程的分步入口，不要在 `start` 仍运行时再同时执行它们。

先完成第1～5节，然后按顺序执行，每一步成功后再进入下一步：

```bash
bash deepseek-run-06/run.sh init
bash deepseek-run-06/run.sh a0 --max-calls 400 --max-tokens 12000000
bash deepseek-run-06/run.sh b --max-calls 6000 --max-tokens 120000000
bash deepseek-run-06/run.sh a --max-calls 400 --max-tokens 12000000
bash deepseek-run-06/run.sh compare
```

分步执行不会自动完成后续步骤，网页需要另开终端运行 `bash deepseek-run-06/run.sh view --port 8086`。

## 14. 哪些操作调用模型

| 命令 | 是否调用模型 |
|---|---|
| `check`、`status`、`view`、`init`、`compare` | 否 |
| `network-check` | 否，但会访问网络检查连接 |
| `probe` | 是，1次小型探测请求 |
| `start` | 是，运行完整实验；已经完成的有效步骤会复用 |
| `a0`、`b`、`a` | 是，执行各自尚未完成的评测或探索 |

离线测试使用模型替身和真实本地仿真，只用于验证程序，不是模型成绩。实际成绩只看这场实验自己生成并核验通过的最终报告。
