## 本次修改

1. 所有 Blue 修复（经验组、无经验组、最终考试）统一提交完整文件：顶层只能包含 `files` 和 `edit`；每个文件只能包含 `file`、`content`。不再使用“查找原文并替换”的补丁接口。
2. 程序先检查回答结构、文件路径、重复/遗漏文件、空代码、Markdown 代码围栏，再应用代码。只允许本题显示且可编辑的文件。接口仍使用 JSON 模式；本地严格检查不等于服务商保证输出一定合规。
3. 每次修复最多一次格式纠正。只有格式不合格或 JSON 无法解析才允许重交；重交前不编译、不仿真，不提供新的功能测试反馈。提示模型保留原修复意图，仅改提交格式。格式正确但编译/功能测试失败，不增加机会；超长无回答和接口异常也不触发格式纠正。
4. 两组、各经验状态的最终考试均使用相同规则。初次回答和纠正后的回答、请求、校验结果、用量分别保留。纠正请求记入真实用量，不伪装成一次免费操作。
5. 真实服务返回的原始正文在清理 JSON 包装前写入运行目录的 `provider_responses.jsonl`。各修复目录的 `blue/submissions/` 保存请求、解析后的回答或错误诊断，正常和失败回答都保留。不记录凭据或内部推理。

## 启动

在项目根目录运行，启动后粘贴密钥并按回车，输入隐藏；无需准备密钥文件。密钥只通过内存中的文件描述符交给实验进程，不保存至磁盘或日志。

```bash
bash prob003-five-round-03/start.sh \
  --run-dir prob003-five-round-03/real-v1 \
  --port 8095
```

`real-v1` 必须是不存在的新目录。端口占用时自动选择后续端口，按终端打印的实际地址打开页面或转发端口。收集结束后自动生成离线报告和审计。默认冻结方案为 `plan-v4/`。
