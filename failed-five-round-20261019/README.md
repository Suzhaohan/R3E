# 上批五个功能失败案例：五轮对抗

完全独立目录，不修改 01，不读取历史模型答案、修复摘要或经验库。
只用上批结果中的五个功能失败案例 ID 选题。
固定 DeepSeek V3-0324，经 OpenRouter；复用用户已配置的本地凭据文件，密钥不复制到本目录。

这次是为 ChipBench 和多文件 Ibex 适配的流程，不是直接复用绑定三题的 01 启动器。
保留五轮在线对抗、空经验静态对照、独立经验、保留缺陷上的严格晋升、统一延后考试。
重要差异：沿用各题的原始基准评分，没有另建独立 evaluator；验证题是独立缺陷，
其测试流与练习、考试同源，因此只能衡量这些基准上的效果。

1. 参考版本通过、缺陷版本失败后开始；Ibex 仅根据公开题面和文件列表选取上下文。
2. 红队从正确版本在线生成两个保留验证缺陷，再逐轮生成一个新缺陷。
   每个出题槽最多两次请求，每次最多四个候选；独立编译、功能筛选，拒绝与考试或既有题重复。
   没有预制备用题；若仍无合格题，明确记录空轮，继续剩余轮次。
3. 每轮静态组为空经验，对抗组只读取本题本次已晋升的经验；两组同题同预算，
   最多两次功能作答，每次至多一次格式纠正。实际语法、编译和测试失败反馈用于第二次作答。
   蓝队不接收干净参考 RTL、参考补丁或红队描述的正确修复方式。
4. 只从对抗组自身成功修复生成经验候选；两个预留缺陷各重复两次，
   相对现有经验必须严格提升且无退步才晋升。验证已满分不提前停止五轮训练。
5. 五题训练全部结束后写入统一经验冻结文件；两组再分别做两次原始考试题。
   最终两组预算相同，考试之间不学习，考试反馈不回流训练。

调用硬上限每题 180 次、全批 900 次（包括格式纠正和有限的传输重试）；不是必须用完。
每次最大输出 16000 token，本地固定 DeepSeek tokenizer 检查输入输出总计不超过 128000。
最多两个案例并行。网络无响应请求可能发生服务端计费，费用以服务账单为准。

```bash
# 离线检查，零模型调用
.venv/bin/python failed-five-round-20261019/run.py --check-only

# 正式运行；相同目录可断点续跑，已有响应必须与当前请求逐字一致
.venv/bin/python -u failed-five-round-20261019/run.py --run --workers 2

# 查看汇总，不调用模型
.venv/bin/python failed-five-round-20261019/run.py
```

`RESULTS.md` / `results.json`：考试汇总；`usage.json`：已返回响应的用量；
`work/<case>/rounds/`：各轮筛选、训练、晋升与经验；
`work/<case>/calls/`：完整请求和响应；`evaluations/`：完整编译和仿真日志。
所有结果只代表原始基准通过情况；Prob017 原题面与参考实现存在矛盾。
