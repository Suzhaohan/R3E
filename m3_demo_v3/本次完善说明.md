六个导入演化电路为 Assignment4V 的全加器、三人表决电路、二选一多路选择器、使能译码器、七段译码器，以及 CirFix 的 3–8 译码器。CirFix 复用仓库中与原始材料同源的公开数据，没有将重复数据计算为新 benchmark。

一个设计的多个缺陷不计作多个独立设计。Assignment4V 按上游设计划分用途，寄存器仅用于回归，计数器仅用于最终留出；合成比较器实例仍共享模板家族。

新增组合电路使用完整二进制输入枚举的 testbench 和相对参考实现的形式验证属性。它们证明与数据集参考实现的等价性，不代表对独立规格的完整正确性证明。保留原始 RTL、testbench 和 diff 内容；原始 `diff.log` 在导入副本中保存为 `reference.patch`，避免与运行日志混淆。

修复了旧节点选择器将非阻塞赋值 `<=` 误选为比较符的问题。设计轮换改为在每种操作支持的设计集合内轮换，避免按整个池的固定步长跳过某些设计。

## 验证结果

- `tests/competition`：45 项通过，包含两套完整五回合执行、恢复、审计重建和证据篡改拒绝检查，耗时约 215 秒。
- 新增设计专项检查：9 项通过，包括可重复构建、集合隔离、实际 Icarus 功能差异、Yosys 反例、精确逆变换和操作边界；整理源补丁文件名后再次通过。
- 57 个 Assignment4V 案例逐一运行：全部参考版可仿真，全部错误版在原始 testbench 下检出功能差异。此结果是输入资格检查，不是修复成功率。
- 数据集文件哈希与案例哈希检查通过；原有四套 benchmark 的 manifest 哈希未改变。
- 前端五回合渲染、设计展示、播放、暂停、单步、重置和完成状态交互检查通过。
- 相关 Core 检查：31 项通过，1 项历史冻结资产哈希检查失败。该失败在未修改的 `m3_candidate_v2` 中也能复现，未改写历史冻结清单来消除失败。

离线五回合实测每轮生成 4 个缺陷，20 个生成缺陷均通过有效性验证，五回合实际覆盖池中的全部 10 个设计。第一回合晋升一次，后四回合未晋升并保留原策略。最终工程回归为静态侧 0/18、对抗侧 18/18；分母为 6 个案例 × 3 个种子。模型替身预置了演化和回归答案，这些数字只说明工程链可执行，不能用于宣称真实模型能力提升。

本次没有调用外部模型，没有产生正式 Strider/Red-Heldout 模型结果。历史发布检查仍因已有设计方案文档中的机器专属工具路径失败；生成缓存和本次导入补丁的日志扩展名问题已清理。本次未执行发布或替换正式冻结结果。

## 运行

从原项目根目录执行：

```bash
bash m3_demo_v3/competition/scripts/run_arena_demo.sh
```

默认五回合完成后访问终端显示的地址（默认 `http://127.0.0.1:8083`），打开 Adversarial Arena。也可以先生成证据：

```bash
bash m3_demo_v3/competition/scripts/run_arena_demo.sh \
  --rounds 5 --output-root /tmp/my-five-round-arena --no-serve
```

输出目录必须是新的空目录。旧三回合证据不会被改写为五回合结果。重新构建输入、资格检查和正式模型实验的步骤分别见 `competition/manifests/README.md`、`开始演示.md` 和 `competition/docs/M3_RUNBOOK.md`。
