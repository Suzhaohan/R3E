The Physical Memory Protection (PMP) logic in Ibex still rejects accesses to the RISC-V Debug Module address range even when the processor core is already in debug mode. If the active PMP rules would normally deny the access, a load, store, or instruction fetch to an address inside the Debug Module range can incorrectly raise a PMP access error. The correct behavior is that, while debug mode is active, PMP must allow loads, stores, and instruction fetches within the Debug Module address range even when those same accesses would otherwise be blocked by PMP. At the same time, accesses outside the Debug Module address range must continue to follow normal PMP checks and must still fault when PMP denies them. This bug affects the PMP permission-check path for debug-mode accesses and is triggered when the core, while in debug mode, accesses an address in the Debug Module range under PMP rules that would otherwise deny the access.
