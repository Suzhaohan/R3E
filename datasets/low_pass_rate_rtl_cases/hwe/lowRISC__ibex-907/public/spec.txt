In the instruction fetch path, the interaction between `ibex_prefetch_buffer` and the fetch FIFO can deassert `instr_req_o` too early when the FIFO is full on a non-branch path and contains a 16-bit compressed instruction followed by a 32-bit instruction that starts in the upper half of one fetched word and completes in the next fetched word. In that state, the next word is requested one cycle late, so after the compressed instruction is consumed the following 32-bit instruction is still incomplete and the core incurs an extra instruction-fetch stall. The expected behavior is that the prefetch buffer must keep requesting the next word needed to complete that spanning 32-bit instruction while the FIFO still holds the compressed instruction and the partial 32-bit instruction, so that once the compressed instruction is consumed the 32-bit instruction is available immediately without an extra fetch bubble.
